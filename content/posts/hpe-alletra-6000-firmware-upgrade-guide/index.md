벤더의 공식 매뉴얼이 있긴 하지만, 실제 필드에서 Alletra 6000 신규 UI를 통해 OS 업그레이드를 진행하며 남긴 기록이다. 처음 작업을 하는 사람의 입장에서 작업 준비 후 실재 진행 하는 화면이 없어서 펌웨어 업데이트 작업을 어렵게 생각 하는부분이 있어서 이번에 정리를 해봤다, 현장 상황이나 버전에 따라 공식 가이드의 순서와 미묘하게 다를 수 있으니 실무 참고용으로 보면 좋겠다.

### 📌 작업 개요
- **현재 OS 버전**: 6.1.2.500
- **타겟 OS 버전**: 6.1.3.300
- **소요 시간**: 약 2시간 내외 (다운로드 및 노드 순차 리부팅, 펌웨어 적용 시간 포함)

---

### 1. 펌웨어 이미지 준비 (인터넷 vs 로컬)

Alletra 스토리지는 OS 업데이트 파일을 준비할 때 두 가지 방식을 지원한다. 작업 환경에 맞춰 선택하면 된다.

- **인터넷 직접 다운로드**: 스토리지가 외부 인터넷(HPE InfoSight 등)과 통신 가능한 환경이라면, 스토리지 UI에서 즉시 버전을 확인하고 다운로드할 수 있다.
- **로컬 파일 업로드**: 폐쇄망이거나 특정 버전을 수동으로 올릴 때, PC에 미리 다운로드해 둔 펌웨어 이미지를 브라우저를 통해 밀어넣는 방식이다.

<br>

### 2. 업그레이드 단계별 진행 순서

**Step 1. 소프트웨어(Software) 메뉴 진입**
관리자 계정으로 접속 후 메인 화면 메뉴에서 `소프트웨어(Software)` 항목으로 진입한다. 현재 설치된 OS 버전(6.1.2.500) 정보와 업데이트 가능한 옵션들이 나타난다.

{{< figure src="step-02-software-menu.png" caption="소프트웨어 관리 메뉴 진입 화면" width="50%" >}}

<br>

**Step 2. 펌웨어 파일 다운로드 및 업로드**
준비한 방식에 따라 진행한다. 
- 인터넷 직접 다운로드 시 '다운로드' 버튼을 클릭하면 스토리지에서 다운로드 가능한 펌웨어 버전 목록이 출력된다.
- 로컬 업로드 시 'Browse(찾아보기)' 버튼을 눌러 PC에 받아둔 펌웨어 파일(.iso/.img)을 선택하고 업로드를 진행한다.

{{< figure src="step-11-internet-download.png" caption="인터넷 다운로드 버튼 클릭 시 나타나는 다운로드 가능 OS 버전 목록 화면" width="50%" >}}

{{< figure src="step-04-summary.png" caption="로컬 업로드용 펌웨어 파일 선택을 위해 'Browse(찾아보기)' 버튼을 누르는 화면" width="50%" >}}

{{< figure src="step-09-completion-stage.png" caption="선택한 펌웨어 파일 업로드 진행 과정 화면" width="50%" >}}

{{< figure src="step-12-download-progress.png" caption="인터넷 다운로드 및 파일 적용 진행 상황 화면" width="50%" >}}

<br>

**Step 3. 사전 점검 (Pre-check) 및 Update 버튼 활성화**
파일 준비가 완료되면 본격적인 업데이트 실행 전 시스템 사전 점검(Pre-check) 로직이 자동으로 돌아간다. 
(안타깝게도 현장에서 캡처를 놓쳐 해당 점검 화면 사진은 누락되었다.) 기존 볼륨 상태나 노드 헬스체크에서 문제가 없어서 정상(Passed) 처리되면, 그동안 비활성화되어 있던 `Update(업데이트)` 버튼이 비로소 활성화된다.

<br>

**Step 4. Update 버튼 클릭 및 소프트웨어 라이선스(EULA) 동의**
활성화된 `Update` 버튼을 클릭하면 최종 소프트웨어 라이선스(EULA) 동의 팝업 창이 나타난다. 라이선스 조항을 확인 후 동의를 진행한다.

{{< figure src="step-05-eula.png" caption="Update 버튼 클릭 후 나타나는 소프트웨어 라이선스(EULA) 동의 화면" width="50%" >}}

<br>

**Step 5. OS 및 펌웨어 업데이트 진행 상태 모니터링**
라이선스 동의를 마치는 즉시 실제 패치 적용이 시작되며, 컨트롤러 노드가 순차적으로 리부팅된다. 신규 UI에서는 진행률(%)과 현재 상태가 직관적으로 표시되므로 차분히 모니터링한다.

{{< figure src="step-08-upgrading.png" caption="OS 업데이트 진행 상태 모니터링 화면" width="50%" >}}

<br>

**Step 6. 업그레이드 완료 및 최종 버전 확인**
모든 노드의 리부팅과 패치 적용이 마무리되면, 대시보드 화면으로 이동하여 타겟 버전(6.1.3.300)으로 정상 반영되었는지 최종 확인한다.

{{< figure src="step-10-upgrade-complete.png" caption="최종 OS 버전(6.1.3.300) 업데이트 완료 확인" width="50%" >}}

💡 **참고**: OS 업그레이드가 진행되는 동안, 하드웨어 컴포넌트의 FW(펌웨어) 업데이트가 필요한 항목이 있다면 프로세스 내에서 자동으로 함께 진행된다.

### 🚨 [주의] 로컬 파일 업로드 시 겪었던 트러블슈팅

이번 작업에서 겪었던 황당한 실수 하나를 공유한다.

처음에는 폐쇄망을 대비해 작업용 PC에서 HPE 포털을 통해 펌웨어 파일을 미리 받아두었다. 파일 용량이 크다 보니 다운로드에 시간이 꽤 걸렸는데, 마음이 급했던 나머지 **다운로드가 채 끝나지도 않은 임시 파일(확장자가 `.part`로 된 파일)**을 제대로 확인도 안 하고 스토리지 UI에 그대로 업로드해 버렸다.

당연하게도(정신이 없어 사진은 남기지 못했지만) 파일 손상으로 인식되어 업로드 실패 에러가 발생했다.

천만다행으로 **해당 스토리지는 인터넷 연결이 되어 있는 장비**였기 때문에, 즉시 방향을 틀어 스토리지 내부 UI에서 인터넷 직접 다운로드를 걸어 작업을 이어나갈 수 있었다. 약 2.5GB 정도 되는 펌웨어 파일이었고, 스토리지 장비가 외부에서 직접 받아오는 데 대략 30분 정도가 소요되었다.

로컬 업로드를 할 때는 반드시 파일 다운로드가 100% 완료되었는지 확인하고 업로드해야 한다. 아주 기본적인 내용이지만, 현장에서는 의외로 하기 쉬운 실수다.

공식 문서의 텍스트만 보는 것보다, 실제 필드의 UI 캡처본을 단계별로 눈에 익혀두면 현장 작업 시 멘탈 관리에 훨씬 도움이 된다. 이번 작업도 무사히 완료.
